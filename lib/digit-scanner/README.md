# Matches/Differs Digit Scanner

A read-only scanner module for Deriv continuous volatility synthetic indices that evaluates past tick digit distributions across 8 statistical heuristics, forms an ensemble consensus, and pre-fills the Matches/Differs trading interface via URL parameters.

## Pipeline Overview

| Step | Function / Module | Description |
|---|---|---|
| 1. Market Selection | `selectVolatilityMarkets(symbols)` | Filters active symbols for `submarket === 'random_index'` matching `/^(R_\d+\|1HZ\d+V)$/`, de-duplicates, and identifies suspended or closed markets. |
| 2. History Retrieval | `scanMarkets(markets, fetchHistory, options)` | Concurrently fetches historical ticks (default 500 ticks, concurrency limit 3) with per-request timeouts. |
| 3. Digit Extraction | `extractLastDigits(prices, pipSize)` | Extracts the last decimal digit using the market's pip decimals (0–12), preserving trailing zeros and discarding non-finite entries. |
| 4. Strategy Evaluation | `STRATEGIES` in `strategies.ts` | Evaluates 8 pure statistical heuristic rules on the digit series. |
| 5. Ensemble Consensus | `analyzeDigits(digits, { minAgree })` | Aggregates strategy votes, applies tie-breaking rules, and calculates a heuristic score (0–100). |
| 6. Market Ranking | `rankMarkets(analyses)` | Ranks consensus markets by score, agreement, eligibility, and symbol name. |
| 7. Trade Hand-off | `buildTradeHandoffUrl` / `parseTradeHandoff` | Pre-fills the Matches/Differs trade page via URL search parameters. |

## Rules

### 1. 200 Valid Tick Minimum
Markets must have at least 200 valid digits after discarding non-finite or corrupted tick prices. Markets with fewer valid ticks receive an `insufficient_data` status with a descriptive message:
`"Insufficient data: X valid tick(s), N required (D invalid dropped)."`

### 2. Strategy Tie-Breaks
When a strategy evaluates both MATCHES and DIFFERS candidates:
- Larger signal strength wins.
- Ties between directions go to `DIFFERS`.
- Ties between digits go to the lowest digit (0–9).

### 3. Ensemble Vote Winner Order
Signal votes are grouped by `direction:digit`. The winner is determined by:
1. Higher summed strength (compared at $10^{-6}$ resolution).
2. More votes (higher vote count).
3. `DIFFERS` before `MATCHES`.
4. Lower digit (0–9).

A recommendation requires at least `minAgree` (default 2) strategy votes.

### 4. Ranking Order
Markets with status `ok` and a non-null recommendation are sorted by:
1. `heuristicScore` descending (rounded to 1 decimal place).
2. `agree` count descending.
3. `eligible` strategy count descending.
4. `symbol` ascending (plain lexicographical string comparison, e.g. `'1HZ100V' < '1HZ10V'`).

The top-ranked market is designated as `selected`. All unranked or errored markets are listed in `excluded` preserving their input order.

### 5. Hand-off Parameters
The hand-off URL format is:
`/?symbol=<symbol>&mode=<DIGITMATCH|DIGITDIFF>&digit=<0-9>&from=scanner`

On navigation, the trade page pre-fills the market, contract mode (`DIGITMATCH` or `DIGITDIFF`), and selected digit. The `HANDOFF_PARAMS` (`mode`, `digit`, `from`) are immediately scrubbed from the browser URL using `window.history.replaceState` to prevent re-triggering upon page reload. User stakes and durations remain entirely untouched.

## Important Disclaimers & Limitations

1. **Independent Pseudo-Random Numbers**: Deriv synthetic-index digits are generated by cryptographically secure pseudo-random number generators designed to be uniform and memoryless. The statistical heuristics implemented here measure past sample variance and noise; they do not predict future random ticks or provide an edge.
2. **Asymmetric Payoffs**: In Deriv Digits trading, a DIFFERS contract pays a small percentage return while a single loss forfeits the entire stake. Conversely, a MATCHES contract pays approximately 9:1 but has a theoretical random probability of 1 in 10.
3. **Correlated Strategies & Multiple Hypothesis Testing**: All 8 strategies share the identical input tick series. Strategy agreement does not represent independent confirmation. Testing multiple heuristics across many markets naturally produces incidental high scores purely by chance.
4. **Heuristic Score Is Not Probability**: The heuristic score (0–100) measures empirical fit to the heuristics relative to eligible rules; it is **not** a win probability, forecast, or statistical likelihood. Past performance or backtest results do not guarantee future outcomes.
5. **Tick Freshness**: Synthetic markets generate new ticks every second. Predictions become stale rapidly; re-scan if time has elapsed before executing a manual trade.
